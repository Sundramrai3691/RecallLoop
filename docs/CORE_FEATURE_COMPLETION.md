### Grounded retrieval correction (2026-11-02)

The confirmed recency/document-order prefilter defect is addressed with indexed PostgreSQL full-text candidate generation: up to 64 sanitized gap-query terms, `simple`-dictionary OR matching, `ts_rank_cd` ordering, stable chunk-ID ties, and a maximum 5,000-row candidate set. A GIN expression index supports the lookup; the application then applies cosine/token ranking, thresholding, and final selection of up to five distinct passages. The real PostgreSQL regression and selected grounding, PDF, and DOCX integration paths passed on a dedicated isolated PostgreSQL 16 target, not the configured application database. On the 5,121-row fixture, the index appeared in the plan; FTS query / final retrieval measured 4.903 / 6.642 ms in one run. This is not a production-scale latency result. Focused retrieval/embedding tests (16) and the server build passed. Known false-negative boundaries remain: no shared lexical term, more than 64 unique terms, or truncation among more than 5,000 matches can exclude a semantically relevant chunk before application-side embedding ranking.
