# Architecture decisions

These records describe decisions evidenced by the implementation and committed history. They are retrospective: the repository does not preserve the original discussion or decision owners, so none are claimed here. See [ADRs](adr/) for concise records.

| ADR | Decision | State / evidence |
|---|---|---|
| [001 PostgreSQL runtime](adr/001-postgresql-runtime.md) | PostgreSQL is the single runtime database, accessed through `pg`. | Accepted; migrations and server wiring are present. |
| [002 Deterministic domain decisions](adr/002-deterministic-domain-decisions.md) | Scheduling, planning, and selection are deterministic; model output is bounded and validated. | Accepted; service and evaluator code. |
| [003 Canonical and personal knowledge](adr/003-canonical-and-personal-knowledge.md) | Shared role knowledge and individual learner evidence use separate models. | Accepted; migrations and knowledge/learner services. |
| [004 User-provided grounding](adr/004-user-provided-grounding.md) | Grounded remediation retrieves from user-provided, owner-scoped text and tracks evidence. | Accepted; migration `010` and grounding services. |
| [005 Independent point evidence](adr/005-independent-knowledge-point-evidence.md) | Structured answers are evaluated and tracked per required point, with aggregate coverage retained for display. | Accepted; migration `011` and recall/question services. |
| [005 Grounding embeddings without pgvector](adr/005-grounding-embedding-storage.md) | Store fixed-dimension embedding values in PostgreSQL `real[]` and rank bounded per-user candidates in application code. | Accepted for the initial implementation; migration `010` and retrieval service. |
| 006 Evidence-gated assessment presentation | Distinguish an absent observed score from a measured zero, prevent baseline query fanout, and require curated MCQ content for deterministic answer-key items. | Implemented in baseline aggregation, question selection, and additive migration `012`; schema validity alone is not quality evidence. |
| [007 Topic and source separation](adr/007-topic-source-separation.md) | Keep the study topic, source URL, and supplied source text distinct; do not synthesize concepts from a URL or absent text. | Implemented in study validation, extraction ordering, and additive migration `013`. |
| [008 Explicit provider configuration](adr/008-explicit-provider-configuration.md) | Provider labels must be recognized; a selected real provider must fail visibly when credentials or responses are invalid rather than silently selecting deterministic behavior. | Implemented in provider factories and safe error mapping; Gemini uses the OpenAI-compatible adapter. |
| [009 Canonical roadmap handoffs](adr/009-canonical-roadmap-handoffs.md) | Preserve learner-selected canonical node IDs through study sessions; keep custom topics unmapped and connect point evidence only on a unique exact match. | Implemented in migration `014`, authenticated roadmap queries, study validation and point evidence persistence. |
| [010 Latest submitted readiness evidence](adr/010-latest-submitted-readiness-evidence.md) | Show My Readiness from deterministic latest submitted canonical point results, keeping partial, incorrect, unanswered, and absent evidence distinct from blended mastery. | Implemented as a read-time projection; PostgreSQL integration coverage exercises outcome classification, tie-breaking, ownership, and stale mastery disagreement. |
| [011 Revisioned canonical question bank](adr/011-revisioned-canonical-question-bank.md) | Keep curated question identity/revisions and canonical point mappings separate from per-learner snapshots; require publication/quality/review gates and preserve the exact revision on attempts. | Implemented in migration `016`, the HTTP pilot seed/quality gate, and the existing assessment/recall path. Independent subject-matter review remains outstanding. |
| [012 Auditable question review and benchmark labels](adr/012-auditable-question-review-and-benchmark-labels.md) | Only an authorized reviewer approval for the exact current question revision can make it eligible for learners; engineering proposals and human labels remain separate until adjudication. | Implemented in migration `017`, the append-only review CLI workflow, learner selector, and machine-readable answer benchmark; no SME approvals or human labels exist yet. |
| [013 PDF ingestion and runtime](adr/013-pdf-ingestion-and-runtime.md) | Parse PDFs in the existing source pipeline with PDF.js; preserve page provenance, bound input/processing, and report no-text files without OCR claims. | Implemented with migration `025`, PDF.js `6.4.299`, Node `>=22.13.0`, page-aware chunk metadata, and text/scanned/malformed browser and PostgreSQL tests. |

Historical feature commits are visible in Git (`git log`); the commit message establishes implementation chronology, not the reasoning or authorship of a formal decision. Revisit a record when the implementation or constraints change.
